# 関連研究の表示（実装済み）

論文詳細ページの「同じDBを使った関連研究」が実質機能していなかった問題の記録。
2026-08 に調査・実測・ブラインド評価を行い、本文ベースの類似度に置き換えた。

実装: `lib/related-papers.ts` / `app/papers/[id]/page.tsx`

## 何が問題だったか

旧実装は、同じDBを使う論文を集めて先頭5件を取るだけだった。

```ts
const related = papers
  .filter((p) => p.id !== paper.id &&
    p.databases_used.some((db) => paper.databases_used.includes(db)))
  .slice(0, 5);
```

`papers.json` は日付降順なので、これは実質「**同じDBを使った最新5件**」になる。

- DPC論文221件すべてで関連研究欄が同一（`pmid-42600244` ほか固定の5件）
- 表示しているのは英語の `title`。`title_ja` は全件あるのに使っていない

## なぜメタデータだけでは解けないか（実測）

| 指標 | 実測 |
|---|---|
| 研究カテゴリの種類 | 9（1論文あたり平均1.31個） |
| 解析手法の種類 | 12（1論文あたり平均0.89個、未付与355/1067件） |
| DB | 10種（未付与267/1067件） |
| MeSH語の付与率 | 540 / 1067 件（51%） |

「DB・研究デザイン・研究カテゴリ」が完全一致する組でグループ化すると、
グループ数255、最大48件（`JADER | 横断的研究 | 安全性・副作用`）、中央値1件。
つまり**48件が同点か、自分だけか**の両極に割れて順位が付かない。

MeSH語も頻出語が Humans(539) / Female(515) / Japan(514) / Male(473) / Aged(435) と
チェックタグで埋まっている。ただし後述のとおり **IDF重み付けと高頻度語カットを入れれば
この問題は自動的に消える**（希少語の 1/5〜1/8 の重みしか持たなくなる）。

→ **関連度の主信号は本文から取る。**

## 使うテキストは英語の title + abstract（日本語ではない）

| フィールド | 文字数 中央値 | 欠損 |
|---|---|---|
| `abstract`（英語） | 1,752 | 11件 |
| `abstract_ja`（AI要約） | 181 | 10件 |

`abstract_ja` は全文訳ではなく2〜3文の要約なので**信号量が約10分の1**。
類似度計算は英語本文で行い、**表示だけ日本語**にする。両方欠損は10件で、
その場合はタイトルのみで計算される（実測でも top1 スコア 0.16〜0.76 を確保）。

## 外部APIは「関連研究リストを埋める」用途には使えない（実測で確認）

### PubMed ELink（pmra / Similar articles）

```
https://eutils.ncbi.nlm.nih.gov/entrez/eutils/elink.fcgi?dbfrom=pubmed&db=pubmed
  &cmd=neighbor_score&linkname=pubmed_pubmed&retmode=json&id=<PMID>&id=<PMID>...
```

- `&id=A&id=B` と繰り返すと入力IDごとに別 linkset が返る（`id=A,B` だと統合されてしまう）
- 1リクエストで数十件のPMIDをまとめられる。レート制限は 3 rps（APIキーで10 rps）
- 近傍は通常100件、スコア付き、自分自身は除外済み

**しかし本サイトのカタログ内被覆率が致命的に低い。** 無作為20件で実測:

| 指標 | 実測値 |
|---|---|
| PubMed類似トップ5のうち自カタログ内 | 平均 **0.65件** |
| トップ20のうち自カタログ内 | 平均 1.60件 |
| 全100件中で5件以上確保できたシード | **3/20（15%）** |

pmraはPubMed全体（約3,700万件）から近傍を返すので、日本のRWD論文1,067件との
交差がほぼ空になる。**これでは5件のリストを埋められない。**

### OpenAlex `related_works`

公式定義は「concepts の共有数が多い**新しい**論文」であり、テキスト類似でも引用でもない。
実測サンプルで **11件中8件が空配列**。使えない。

### Semantic Scholar

Recommendations API / SPECTER2埋め込みは品質面では最有力だが、2024年8月以降
**フリーメールドメインからのAPIキー申請を受け付けない**方針が公式に明記されており、
gmail.com + 個人サイトでは事実上取得できない。匿名プールは全ユーザー共有かつ削減方針で、
「低メンテナンス」原則に反する。

### 結論

外部APIは**リストを埋める用途では不採用**。ただし「カタログ外への広がり」は
**APIコール不要の外部リンク**で提供できる（後述）。

## 手法の質は頭打ちしている（自前BM25で十分な根拠）

- **RELISH ベンチマーク**（1,500人超の研究者が18万超のPubMed論文ペアを手動評価、
  90%超は原著者本人による判定）: **BM25 / TF-IDF / pmra の3手法は総合性能がほぼ同等**。
  ただし推薦する論文集合が異なるため、ハイブリッドが望ましいとされる。
  <https://academic.oup.com/database/article/doi/10.1093/database/baz085/5608006>
- **Lin & Wilbur 2007（pmra原論文）**: TREC Genomics で BM25 に対する改善は
  「小さいが統計的に有意」なレベルにとどまる。
  <https://bmcbioinformatics.biomedcentral.com/articles/10.1186/1471-2105-8-423>
- **Sjögårde & Ahlgren, JASIST 2024**: 引用ベースとテキストベースの**組み合わせ**が
  単独手法を上回る。<https://asistdl.onlinelibrary.wiley.com/doi/10.1002/asi.24951>

→ 「PubMedと同じ精度でないと」という心配は不要。**BM25＋タグの組み合わせが正しい方向。**

参考実装として arxiv-sanity-lite は TF-IDF(1-2gram, max_features=20000, min_df=5,
**max_df=0.1**, sublinear_tf) + LinearSVC を使っている。`max_df` で高頻度語を切る発想は
本サイトのチェックタグ問題にそのまま効く。
<https://github.com/karpathy/arxiv-sanity-lite/blob/master/compute.py>

## 他サイトの提示スタイル

| サイト | 件数 | 「なぜ関連か」の説明 |
|---|---|---|
| PubMed | 初期5件＋"See all similar articles" | なし |
| Semantic Scholar | 10件前後（TLDR要約付き） | なし |
| Connected Papers | グラフ（バブル＝被引用、色＝年） | あり（グラフ上の距離・経路） |
| Google Scholar | 検索結果形式 | なし |
| ニュース系 | 3〜6件 | タグ表示が一般的 |
| EC | 4〜8件 | 「よく一緒に購入されている」等の明示ラベル |

学術系はほぼ説明を出さない。一方で推薦システムの研究では、説明の付与が
透明性・信頼・目的の項目への到達速度を改善することが一貫して報告されている。

→ **本サイトはDB・手法・領域のタグを自前で持っているので「なぜ関連か」を出せる。
学術系サイトが差別化できていない領域であり、ここが最大の勝ち筋。**

## 実測: ローカルBM25は実際に効く

英語 title(×3) + abstract を語単位でトークン化、簡易ステミング、ストップワード除去、
df<3 と df>25% を捨てて BM25(k1=1.5, b=0.75) 重み付けの L2 正規化ベクトル、
転置索引でコサイン上位を取る。**外部依存ゼロ、純Node。**

| 項目 | 実測 |
|---|---|
| ベクトル構築 | 約 0.3〜0.5 秒（語彙 7,919） |
| 全1,067件の上位10近傍探索 | 約 1.2〜1.4 秒 |
| **合計** | **約 1.9 秒**（`npm run build` はこの環境でコールド27.2秒） |
| 上位5近傍のうち**別DB**の論文 | **64%** |
| 上位5近傍のうち研究カテゴリ一致 | 60% |
| top1 が相互に上位5入りする割合 | 85% |
| DPC先頭20件の上位5近傍 | のべ100件中**ユニーク90件**（現状は全件同一） |

スコア分布と閾値:

| 閾値 | 5件揃う | 3件以上 | 0件 |
|---|---|---|---|
| 0.10 | 1063/1067 | 1066 | 0 |
| **0.15** | **810** | **950** | **16** |
| 0.20 | 355 | 581 | 172 |

top1スコアの中央値は 0.278、top5スコアの中央値は 0.178。

出力例（「認知機能障害が膝関節形成術後のせん妄・退院先に与える影響」）:

```
0.426 脳血管疾患と膝関節置換術後の認知関連合併症：全国コホートからのエビデンス [DPC]
0.378 高血圧は膝関節形成術後の深部静脈血栓症リスクを増加させる [DPC]
0.367 超高齢膝関節形成術患者における肺炎・認知機能障害・脳血管障害リスクの上昇 [DPC]
0.346 単顆置換術と全置換術後の重大な全身合併症リスクの年齢層別比較 [DPC]
0.337 認知機能障害を有する高齢大腿骨近位部骨折患者における術後合併症リスクの増加 [DPC]
```

**失敗モードも実測できている。** JADER論文（光免疫療法の有害事象）では第3位に
無関係な「大腸憩室炎の結腸膀胱瘻」が 0.190 で紛れ込む。**閾値による足切りは必須。**

タグ一致による加点を掛けると、このノイズは順位こそ変わらないが相対的に沈み、
別DB割合は 64% → 58% になる。**タイブレークとしては有効だが、単独では効かない。**
（試行時は同DBを最優先にしていたが、最終的な重みは同カテゴリを優先している。後述）

## 1回目のブラインド評価: 本文ベースへの置き換え（採用）

実装前に、20本を使用DBで層化抽出し（DPC 4／JADER 2／JMDC 2／NDB 2／NCD・MDV・
NDBオープンデータ・DeSC・MID-NET 各1／**DBなし5**）、新旧2手法の出力を混ぜて
シャッフルし、**どちらの手法由来かを伏せた**状態で採点させた。

評価者は2名（別モデル）。互いのやり取りは無し。同一のルーブリックで0〜3点:
3=強く関連 / 2=関連あり / 1=DBや手法が同じだけ / 0=無関係。
「同じDBを使っている」だけでは2点以上にしないよう明示的に指示した。

### 結果（2名の平均点。のべ163スロット、ユニーク候補160件）

| | 平均点 | 2点以上 | 0点 | 候補が出た論文 |
|---|---|---|---|---|
| **新実装（BM25+タグ）** | **2.11** | **65%** | **1%** | **20/20** |
| 旧実装（同DB最新5件） | 0.63 | 13% | 52% | 15/20 |

評価者間の一致は **完全一致64% / ±1以内99% / r=0.89**。採点は十分に安定している。

**両評価者が独立に、同じ失敗パターンを指摘した。** 「胃切除後の漢方薬処方」
「気温と全死因入院」「心嚢液貯留の病因」など同じ数本が、脳梗塞・脳神経外科・
透析患者の化学療法といった無関係なシードに繰り返し現れる、という指摘である。
答え合わせの結果、**それらはすべて旧実装の出力だった**。

seed別で旧実装が上回ったのは MID-NET の1件のみ（2.3 対 2.0）。MID-NETは
全体で7件しかないため「同じDB」がそれ自体で極めて限定的な条件になる特殊例。

### 閾値の決定

BM25素点の帯ごとに評価点を見ると単調に上がる（相関 r=0.40）。

| 素点の帯 | 件数 | 平均評価 | 2点以上 | 0点 |
|---|---|---|---|---|
| 0.15〜0.18 | 18 | 1.86 | 50% | 6% |
| 0.18〜0.22 | 20 | 1.88 | 70% | 0% |
| 0.22〜0.28 | 21 | 1.90 | 48% | 0% |
| 0.28〜0.40 | 22 | 2.48 | 77% | 0% |
| 0.40〜 | 7 | 2.86 | 100% | 0% |

閾値を上げても質はほとんど変わらない（平均2.11→2.29）のに、候補が出る論文が
20/20 → 15/20 まで落ちる。**0.15 を採用**。この閾値でも0点は1%に収まる。

## 2回目のブラインド評価: 診療領域・トピックの加点（採用）

診療領域(subfield)と細かいトピック(topic)をタグ加点に足すかを検証した。

先に本文類似度だけでどれだけ話題が揃うかを測ると、上位5近傍4,721件のうち
同じトピックを持つのは27%（無作為2件が一致する確率0.8%の**34倍**）、
同じ診療領域は34%（同4.7%の7倍）。本文だけでも強く効いているが、
66%は領域が異なっており改善の余地がある。

重みを差し替えたときの影響は限定的で、**上位5の顔ぶれは93%が同じ**。
そのため1回目と同じやり方で全候補を採点しても差が埋もれる。
**新旧で食い違ったスロットだけ**を取り出し、共通候補をアンカーとして混ぜて
36 seedを2名（別モデル）にブラインドで採点させた。

| | 件数 | 平均点 | 2点以上 | 0点 |
|---|---|---|---|---|
| **新重みだけが選んだ候補** | 39 | **2.17** | 67% | 0% |
| 旧重みだけが選んだ候補 | 39 | 1.46 | 38% | 8% |
| 両者が共通で選んだ候補（アンカー） | 36 | 2.39 | 83% | 0% |

seed単位で **26勝6敗4分、差の平均 +0.76点（SD 1.20, n=36, t=3.80）**。
評価者間の一致は完全一致68% / ±1以内100% / r=0.88。**採用。**

採用した重み: topic 0.18 / area 0.08 / category 0.12 / database 0.06 /
method 0.05 / design 0.03。トピックは364種あり完全一致がきわめて具体的な
信号になるので最も高くし、その分カテゴリとDBをわずかに下げた。

## 3回目のブラインド評価: トピック加点をIDFで薄める案（不採用）

2回目で負けた6 seedのうち、差が大きい上位2件がどちらもJADER論文だった。
原因はトピックの偏りにある。

| トピック | 件数 | 内訳 |
|---|---|---|
| Pharmacovigilance and Adverse Drug Reactions | 50 | うち47件がJADER（JADER論文127件の37%） |
| 1件のみのトピック | 163種 | 一致すればきわめて具体的 |
| 2〜5件のトピック | 158種 | 同上 |

最大トピックの一致は「同じ薬剤・同じ疾患」ではなく「これは安全性研究である」と
いうラベルにしかならない。そこで本文のIDFと同じ理屈で、頻出トピックの加点を
出現件数で薄める案を作った（1件で満額、50件なら11%）。

既存の採点データで見るとJADER seedの平均が 1.92 → 2.23 に回復し、全体平均も
下がらなかった。**しかしこれは採点済みの75/180スロットだけを使った部分的な測定で、
しかも採点対象が比較した2案から作られている循環した測り方だった。**

影響を受ける96 seedから30件を抜き、同じ差分方式で改めて2名に採点させた結果:

| | 件数 | 平均点 | 2点以上 |
|---|---|---|---|
| 薄めた方だけが選んだ候補 | 32 | **1.59** | 44% |
| 薄めない方だけが選んだ候補 | 32 | **1.95** | 69% |
| 共通（アンカー） | 30 | 2.37 | 80% |

seed単位で **8勝17敗5分、差の平均 −0.35点（SD 0.99, n=30, t=−1.94）**。
評価者間の一致は完全一致63% / ±1以内100% / r=0.84。

**薄めた方が悪化したので不採用**（コミット後にrevert）。頻出トピックで得るものより、
効いている側を弱める損の方が大きい。部分データでの事前確認が誤導した例として、
**同じ方向で再挑戦しないこと。**

### JADERが弱いのは本文側の問題

3回目の評価者2名がそろって原因を指摘している。JADER/FAERSの薬剤疫学論文は
抄録の語彙（ROR / PRR / BCPNN / 不均衡分析 / シグナル検出）が極端に均質なため、
**本文類似度が被疑薬名ではなく方法論の定型文に反応している**。
実際「候補3〜5件すべてが同じ様式のシグナル検出研究で、被疑薬も有害事象も
重ならない」というseedが複数あった。

`MAX_DF_RATIO` は25%だが、JADER論文はコーパスの12%しかないため
これらの定型語が生き残る。手を入れるなら**ストップワード側**であって、
トピック加点ではない。未検証の仮説なので、やるなら同じ差分方式で測ること。

## 実装内容

```
score = BM25コサイン(英語 title×3 + abstract)
      × (1 + 0.18·同トピック + 0.12·同カテゴリ + 0.08·同診療領域
           + 0.06·同DB + 0.05·同手法 + 0.03·同デザイン)
足切り: BM25コサイン >= 0.15、上位5件
```

- **同じDBより同じ話題（トピック・カテゴリ）を優先**
- 単一リストのまま。セクション分割はしない
- 見出しは「同じDBを使った関連研究」→「**関連研究**」
- カードは**英語タイトルを主・日本語タイトルを副**として併記（一覧の `PaperCard` と
  同じ扱いに揃えている）。DB／研究カテゴリ／研究デザインのバッジを出す。
  カード全体が `<Link>` なのでどこを押しても飛ぶ
- **閾値に届かなければ5件に満たなくてよい**。無関係な論文で枠を埋めない

### 実測

| 項目 | 値 |
|---|---|
| 関連研究が5件出る論文 | 821/1067 |
| 4件 / 3件 / 2件 / 1件 | 68 / 63 / 56 / 43 |
| 0件（欄自体が出ない） | **16/1067** |
| ビルド時間 | 23.6秒 → **25.0秒**（+1.5秒） |

ビルド時間は、詳細ページを旧ロジックに戻したものと入れ替えて実測した差。
一度 38.2秒 と記録したことがあるが、これは裏で別の処理を回しながら計測した
ノイズで、実際の増分は1.5秒程度。

事前計算した `data/related.json` をコミットする方式は採らなかった。
`data/papers.json` は週次のRoutineが書き換えるため、ビルド時計算にしておけば
論文が増えても自動で追随し、運用が増えない。

### 転送量への影響はゼロ

詳細ページはサーバコンポーネントなので、関連研究はビルド時にHTMLへ焼き込まれる。
既知の課題2（`/papers` 一覧が728KB。当時の値）には影響しない。

## 採用しなかった案

| 案 | 理由 |
|---|---|
| **セクション分割**（テーマ順・別DB枠・同DB新着枠） | 単一リストで十分と判断。実装しない |
| **PubMedへの外部リンク** | 見送り |
| **同じ著者の研究** | 著者名が `Tanaka H` 形式で名寄せ不能。`Fushimi K` 122件・`Yasunaga H` 108件は実在の多産著者だが、`Tanaka H` 36件は確実に別人混在。ORCID / OpenAlex著者IDを取らない限り危険 |
| **共引用・書誌結合** | 対象が2025〜2026年の論文（502件+565件）で被引用がほぼゼロ |
| **お気に入りベースの推薦** | `lib/favorites.ts` はlocalStorageのみでサーバ集計不可。クライアントで回すには類似度データの配信が必要で、課題2の転送量と衝突する |
| **MMRによる多様化** | 同DB・同手法の論文群なので近重複がもともと少なく、効果が小さいことを実測で確認 |
| **SPECTER2などの埋め込み** | Python依存か23MBのONNXモデルをビルドに持ち込む。RELISHの結果からBM25との差は限定的で、「無料・低メンテナンス」原則に見合わない |

## 疾患・診療領域の軸（実装済み）

以前は DB(10) / 研究カテゴリ(9) / 解析手法(12) / 研究デザイン(4) しか軸が無く、
**「何の病気の研究か」を表す軸が1本も無かった**。研究カテゴリは「安全性・副作用」の
ような研究の性格を表すもので、疾患領域ではない。

OpenAlex の primary_topic をこの軸に採用した。

```
https://api.openalex.org/works/pmid:<PMID>?select=id,topics,keywords
```

| 項目 | 実測（全1,067件） |
|---|---|
| 取得成功 | **1,062/1,067**（失敗5件はOpenAlexに未収載） |
| コスト | `x-ratelimit-cost-usd: 0` — **singleton は課金対象外** |
| ライセンス | **CC0**。再配布・リポジトリ保存すべて自由 |
| バックフィル所要 | 0.25秒間隔で約10分（`scripts/backfill-openalex.ts`） |

当初は「第2・第3トピックはスコア 0.00〜0.06 でほぼノイズ」として第1のみを採っていたが、
2026-08-27 に全1,085件で取り直したところ、これは**中央値だけを見た判断**だった。

| | 中央値 | p90 | 最大 |
|---|---|---|---|
| 第1トピック | 0.906 | 0.998 | 1.000 |
| 第2トピック | 0.044 | **0.354** | **1.000** |
| 第3トピック | 0.013 | 0.138 | 0.999 |

第1の確信度が高い論文では第2が 0.008 まで落ちるが、低い論文では第2に意味のある
スコアが載る。1論文が複数の診療分野にまたがることを表すにはこの第2以降が要るため、
`?select=id,topics` で全件を取り `openalex_topics`（`{name, score}` の降順配列）に保存している。
`openalex_topic` は互換のため第1と同じ値を残してある（取り直し後も不一致0件）。

### どの粒度を軸にしたか

OpenAlex のトピックは topic → subfield → field → domain の階層を持つ。

**2026-08-27 追記: subfield は使うのをやめた。** topic→subfield は OpenAlex 側の
固定写像（370トピック中、subfield が割れるものは0種）で、その表自体が誤っている。
`Gastric Cancer Management and Outcomes` の親が `Pulmonary and Respiratory Medicine`
なので、胃癌の論文が全部「呼吸器」に入る。subfield「呼吸器」82件のうち半分
（胃癌12・前立腺癌8・大動脈6・乳癌3 …）が無関係だった。MeSH を正解データにすると、
胃癌11件中7件・前立腺癌3件中2件が「呼吸器」に落ちていた。

代わりに `data/topic-areas.json`（トピック→診療分野の辞書、25分野／679トピック）を
自前で持ち、`lib/clinical-areas.ts` で引いている。辞書なら誤りを直せるうえ、
1トピックに複数の分野を持たせられる。

| 階層 | 種類数 | 判断 |
|---|---|---|
| `field` | 13種（うち "Medicine" が79%） | 粗すぎる。不採用 |
| ~~`subfield`~~ | 74種 | **不採用**。写像が誤っている（下記）。独自辞書に置き換えた |
| `topic` | 364種 | ファセットには多すぎる。詳細ページに表示のみ |

診療領域の分布（上位）:

| 件数 | 領域 |
|---|---|
| 129 | Surgery |
| 84 | Epidemiology |
| 82 | Pulmonary and Respiratory Medicine |
| 77 | Oncology |
| 63 | Cardiology and Cardiovascular Medicine |
| 50 | Toxicology |

上位8種で 562/1067件をカバーする一方、5件未満の領域が31種ある。
サイドバーに74種すべてを並べると極端に長くなるので、
**上位8種＋「すべて表示 (+66)」**で折り畳む（選択済みの値は折り畳み中も必ず見せる）。

### カンマを含む領域名の罠

絞り込み値のURL解析は、古いカンマ区切りURL（`?db=DPC,JMDC`）との互換のために
カンマで分割している。ところが診療領域には
`Public Health, Environmental and Occupational Health` のようにカンマを含む値が
**5種・99件**あり、そのままだと2つの条件に割れて0件になる。

診療領域は後から追加した軸でカンマ区切りの古いURLが存在しないので、
`parseList` に分割しないオプションを足して回避した。同じ理由で
`databases.json` の `paper_tag` にはカンマ禁止のガードが入っている。

### 転送量

`/papers` は全論文をページに埋め込んでいるため、フィールドを4つ増やすと重くなる。
実測（フィールドを削ったビルドとの比較）:

| | raw | brotli |
|---|---|---|
| 診療領域なし | 3,818KB | 711KB |
| 診療領域あり | 3,999KB | **723KB** |

**+12KB（+1.7%）**。領域名は74種しかなく繰り返しが多いのでbrotliがよく効く。

## 解決済み: IF取得が無言で失敗していた件

`scripts/sync-pubmed.ts` のインパクトファクター取得が list形式のエンドポイントを
叩いており、OpenAlexの2026-02の従量課金移行後は 429 を返すようになっていた。

```
旧 https://api.openalex.org/sources?filter=issn:1438-8359  → 429 Insufficient budget
新 https://api.openalex.org/sources/issn:1438-8359         → 200, cost 0
```

singleton形式は課金対象外で、残高が尽きていても200を返す。**課金は不要だった。**
`try/catch` で握りつぶしてIFが無言でnullになっていたため、404以外は
警告を出すようにもした（404は「そのISSNがOpenAlexに無い」で想定内）。

polite pool 用の `mailto` は環境変数 `OPENALEX_MAILTO` から渡す。
以前はダミーの `rwd-catalog@example.com` が埋め込まれていた。

## 既知バグ（トークナイザ）

コードレビューで出た2件。**1は一部修正済み、2は未修正。**

### 1. `stem()` に最短長のガードが無い → 一部修正済み（2026-08-25）

`(ing|ed)$` を無条件に落とすので、同じ語が別のトークンに割れていた。

**直した部分**

- **語尾を落とすのは残りが3文字以上のときだけ**にした。以前は
  `bed`/`beds`→"b"、`ring`/`rings`→"r"、`hrs`→"hr"、`los`→"lo"、`aes`→"ae" と潰れ、
  3文字未満は `tokenize` が捨てるので索引から消えていた。
  実測で **116種・延べ7,363回が消失 → 0**。DPC研究の「病床」、ハザード比(hrs)、
  在院日数(los)、有害事象(aes) が該当する。
- **`-eed` で終わる語を除外**した（Porter step 1b と同じ）。これが無いと
  `bleeding`→"bleed" と `bleed`→"ble" が割れる。出血は抗凝固薬の安全性研究の
  中心的な語なので、割れると近傍の質に響く。
  `bleed`/`bleeds`/`bleeding`、`feed` 系、`need` 系、`exceed` 系がまとまった。

関連件数の分布は修正前後でほぼ不変（5件表示 821→818件、0件 16→19件）。
**順位が良くなったかは測っていない。**

**直していない部分（語尾の e の復元）**

| 語 | ステム | 語 | ステム | 一致するか |
|---|---|---|---|---|
| dosing | dos | dose | dose | ✕ |
| imaging | imag | image | image | ✕ |
| staging | stag | stage | stage | ✕ |
| based | bas | base | base | ✕ |
| aging | aging | aged | aged | ✕（消えはしなくなったが別トークン） |

Porter step 1b の「cvc で終わるなら e を足す」を入れれば上4行は直る
（`dos`→`dose`、`imag`→`image`）。ただし `increased`→"increas" と
`increase` の分裂は Porter でも残る。**順位が変わるので、ブラインド評価とセットで。**

**新たに見つかった同種の問題（未修正）**

複数形規則 `([^s])s$` が `-sis` / `-us` で終わる**単数形**も削っている。
`analysis`→"analysi"（1,037回）、`diagnosis`→"diagnosi"（469回）、
`status`→"statu"（148回）、`osteoporosis`/`dialysis`/`prognosis`/`thrombosis`/
`sepsis`/`colitis` など **289種・延べ5,725回**。

全論文が同じ処理を通るので**取りこぼしは生まれない**。実害は
`focus`→"focu" と `focused`→"focus" のような語族の分裂だけ。
`([^s])s$` を `([^siu])s$` にすれば直る（`lib/papers-search.ts` の
`PLURAL_S` は同じ理由で `[^siu]` にしてある）。これも順位が変わる。

### 2. `tokenize()` が `normalizeForSearch()` を使っていない → 未修正

検索側（`lib/papers-search.ts`）は英米綴りや異体字を正規化して照合している
のに、関連研究のトークナイザは自前の小文字化＋分割しかしていない。

コーパス実測: tumour 7 対 tumor 40 / oesophag 6 対 esophag 32 /
ischaemi 6 対 ischemi 25 / paediatric 4 対 pediatric 40 / randomised 1 対 randomized 11。
`randomised` は `MIN_DF = 3` でそもそも捨てられる。
`normalizeForSearch` を再利用すれば済む。

なお `normalizeForSearch` には 2026-08-25 に複数形吸収（`PLURAL_S`）が入った。
2 を直すと、その規則も関連研究側に効く。
