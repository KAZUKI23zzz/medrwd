# 関連研究の表示（未着手・独立課題）

論文詳細ページの「同じDBを使った関連研究」が実質機能していない問題の引き継ぎ資料。
本体の改修（検索・絞り込み）とは独立して進める。

## 現状の何が問題か

`app/papers/[id]/page.tsx` の実装は、同じDBを使う論文を集めて先頭5件を取るだけ。

```ts
const related = papers
  .filter((p) => p.id !== paper.id &&
    p.databases_used.some((db) => paper.databases_used.includes(db)))
  .slice(0, 5);
```

`papers.json` は日付降順なので、これは実質「**同じDBを使った最新5件**」になる。
DPC論文なら221件の候補から常に同じ5件が出るため、どのDPC論文を開いても
関連研究の欄がほぼ同一になる。話題の関連性はまったく見ていない。

## なぜ難しいか（実測値）

過去に何度か試みて上手くいっていないが、原因はデータ側にある。
**メタデータの粒度が粗すぎて、関連度の判定に使えない。**

| 指標 | 実測 |
|---|---|
| 研究カテゴリの種類 | 9 |
| 解析手法の種類 | 12 |
| 1論文あたりの平均カテゴリ数 | 1.31 |
| 1論文あたりの平均解析手法数 | 0.89 |
| MeSH語の付与率 | 540 / 1067 件（51%） |

「DB・研究デザイン・研究カテゴリ」が完全に一致する組でグループ化すると:

- グループ数 255、**最大グループは48件**（`JADER | 横断的研究 | 安全性・副作用`）
- 上位5グループは 48, 47, 42, 42, 38 件
- 中央値は1件（＝ほとんどのグループは1件だけ）

つまりメタデータだけでは「48件が完全に同点」か「自分だけ」の両極に割れる。
**順位付けができない。** これが過去の試みが失敗した理由と考えられる。

MeSH語も使えない。付与率が51%な上、頻出語が Humans(539) / Female(515) /
Japan(514) / Male(473) / Aged(435) とチェックタグ的な語で埋まっており、
これで類似度を測ると「日本人・女性を含む研究」同士が似ていることになってしまう。

→ **関連度の信号は本文（title / abstract）から取るしかない。**
   幸い `title_ja` は全件、`abstract_ja` も99%ある。

## 他サイトのやり方（未検証・一次情報に当たること）

以下は一般的な知識にもとづく整理で、**このセッションでは一次情報で裏を取っていない**。
検索・絞り込みの調査（`docs/` 外、コミット f1376a7 の議論）では公式ヘルプに
当たって裏を取ったが、この項目は未実施。実装前に確認すること。

- **PubMed の Similar articles** — 抄録とタイトルの単語から重み付きベクトルを作り、
  文書間の類似度で並べる方式（pmra アルゴリズム）とされる。単語の希少性で重み付けし、
  よくある語の影響を下げるのが要点。**NLMの技術文書で要確認。**
- **Semantic Scholar / Connected Papers** — 引用関係のグラフを使う。
  共引用（同じ論文に引用されている）や書誌結合で近さを測る。
  **本サイトは引用データを持っていないので採用できない。**
- **一般的なECサイト** — 行動ログ（一緒に見られた/買われた）。
  **本サイトはアクセスログを持たない静的サイトなので採用できない。**

つまり本サイトで使えるのは**本文ベースの類似度**だけ。引用も行動ログもない。

## 現実的な選択肢

静的サイト（サーバなし・ビルド時に全件アクセス可能）という前提での案。

1. **TF-IDF + コサイン類似度をビルド時に計算し、各論文の上位N件をJSONに焼き込む**
   - 1067件なら全ペア約57万通り。ビルド時に一度計算すれば済む
   - 日本語は分かち書きが要る。形態素解析器を入れずに済ませるなら文字N-gram（bi-gram）が現実的
   - 英語の `title` + `abstract` だけで計算する手もある（99%が英語抄録を持つ）
   - 出力は `data/related.json` のような別ファイルにして、詳細ページで引くだけにする
2. **上と同じだが、メタデータで軽く重み付け**（同じDB・同じ解析手法なら少し加点）
   - メタデータ単体では効かないが、本文類似度のタイブレークには使える
3. **何もしない代わりに、正直な見出しに変える**
   - 「関連研究」をやめて「同じDBを使った最新の研究」にする。実装と表示が一致する
   - 上記1が難しいと判断した場合の最低ラインとして有効

推奨は 1 →（効果を見て）2。3 は暫定措置として即座に適用できる。

## 検証の勘所

- 「関連が良くなった」を主観で判断しない。**同じDBの論文を3件開いて、
  関連研究の欄が実際に別物になるか**を最初に確認する（現状はほぼ同一）
- 頻出語に引きずられていないか。`Humans` `Japan` `retrospective` のような語で
  似ていることになっていないか確認する
- ビルド時間への影響を測る。現在の `npm run build` は約13秒
